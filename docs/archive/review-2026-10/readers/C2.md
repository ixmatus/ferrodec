### C2-1 evidence
Reproducer crate `C2/arith` runs the d128/d64/d32 ops against `oracle::*` with exactly parsed operands: `printf '128 tz fma 10E0 1000000000000000000000000000000000E0 -1E-102\n' | target-C2/release/arith` → `MISMATCH ... got 9999999999999999999999999999999990 Status(16) want 9999999999999999999999999999999999E0 Status(16)`. Independent confirmation: O-mpd `Context(prec=34, ROUND_DOWN, clamp=1).fma(10, 10**33, Decimal('-1E-102'))` gives `9999999999999999999999999999999999`, Inexact; O-Frac: the exact value lies strictly between 10^34 − 1 and 10^34. Extent: `C2/fma_family.txt` has 43,830 cases and 3,366 mismatches, all d128: TowardZero 1,683, TowardNegative 1,122, TowardPositive 561; none under the nearest modes and none on d64/d32. The defect appears once the gap reaches 76: digits(cab) = 35, and 35 + 76 > `BUFFER_DIGIT_LIMIT` = 110 (fma.rs:67, 357); a closer addend such as −1E-40 is correct. Trace: `fma_finite_kernel` takes `ab_too_wide` → `fma_sub_ulp` → `fma_ab_dom_in_range_eff_sub` (fma.rs:538, 687); with 35 digits one digit is dropped, `kept = 10^33`, round digit 0, sticky false; the branch at fma.rs:791 applies `kept.sub(1)` yielding 33 nines at `kept_q` (line 804); `round_and_pack_finite` pads toward `min(qab, qc)`, giving `999…990E0` = 10^34 − 10; the correct lower neighbour is 10^34 − 1 at `qab`. The c-dominates twin is clean on 360 power-of-ten addend cases. Why missed: property_fma_oracle's `arbitrary_finite` draws coefficients uniformly, so an exact 10^k product with k ≥ 34, opposite sign, gap ≥ 76, and a directed mode is never sampled; fd-7nf pins the divides-evenly facet at a near gap only; dqFMA has no vector of this shape (1,418/1,418 pass); Kani is special-only; the sibling FMA implementations are separate code and clean.

## Design notes
1. The 10-constant Kani operand selector puts every zero at exponent 0, so exponent, cohort and CLAMPED behaviour of the special paths is unseen.
2. The oracle loop passes through code under test (operands via `{:e}`, expected re-parsed through `parse_str`); `decode_decimal*` on both sides would remove that dependence.
3. Three hand-copied decTest parsers use different NaN comparators (bits, Display, is_nan); one shared comparator would fix C2-5.
4. Special-case dispatch order is a recurring defect class (C2-2, C2-3, C2-4 are early-return bugs); a shared `nan_dispatch2` helper would remove the per-op choice.
5. Property strategies lack structured coefficients (powers of ten, all nines, 5·10^k at extreme gaps); that would have found C2-1.
