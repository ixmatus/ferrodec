### C4-1

Command: `$SCRATCH/C4/run_clippy.sh` (per crate `cargo clippy -p <crate> --lib --all-features --message-format=json -- -W clippy::<each of the 24 allowed lints>`), counted by `count.py`. `missing_panics_doc` library sites: d64 11, d32 8, `ferrodec-decimal` 13, multiword 2, root 0. B4-7 (P0, interop.rs:40/:54) and the B4-5/6 `fma` panic (arith.rs:251/:272) are the first, second, third and fourth rows. The lint asks only for a `# Panics` section, but writing that section forces the author to state the precondition ("panics if the payload exceeds the target's digits"), which is the sentence that would have exposed B4-7. The allow's rationale in Cargo.toml (:24-50) does not mention `missing_panics_doc` at all; it is one of the entries with no stated reason.

Why the stack missed it: clippy is the instrument and the battery runs it at `-D warnings`, but the allow list removes this lint before it runs; no other instrument looks for undocumented panics on the public surface.

## Design notes

1. **One decode, one align.** The three fixed format crates decode operands with the same three copy `match Class { Finite, Zero, _ => unreachable!() }` block in `add_inner`, `fma`, `rem_*`, `quantize` (d64 fma.rs:160-185 is the clearest), and express "borrow one ULP and re-extend" three ways (addsub inline, fma `h2_borrow_and_extend`, fma overlap path without it). B2-1 is the defect this shape produced: 7655b7c added the overlap path one day after d819e83 added the helper, and the new path folded its truncated side into a positive sticky. A `decode_finite` returning newtypes (C4-4) and one `align_with_residue(dominant, other, effective_sub)` used by addsub, fma and rem would make the class unrepresentable.
2. **Six parsers of one grammar.** Each crate has `parse_str_inner` and a `const fn parse_literal` (src/convert/parse.rs:203, :421 and the sibling pairs) agreeing only on the accepted subset by property test. A per crate `const fn` lexer returning `(sign, digits, point, exponent field)` that both consume would hold the H8 caps, the ADR-0057 sentinel and the NaN payload bound once; a format parameterised lexer in `ferrodec-ieee` would hold them once for the workspace (B3-5 and C4-10 are the receipts).
3. **`(value, Status)` is right; `#[must_use]` on the tuple is weak.** `let (x, _) = a.add(b, rm)` discards status silently and the examples do it everywhere. A `#[must_use]` `Status` type (the attribute on the struct, `ferrodec-ieee/src/status.rs:22`) would warn on a dropped flag set without changing a signature; evidence that would make it a finding: a shipped caller that drops an INVALID it needed. `Status` also has only `Debug` (status.rs:22, :147), so every example prints booleans by hand.
4. **Twin names.** root `finalize_finite` (round.rs:289) against siblings `finalise_finite`; root `src/math/{exp,ln}.rs`, `hyperbolic.rs`, `sincos.rs`+`inverse_trig.rs`, `format_impl.rs` against siblings `ops/exp.rs`, `ops/hyper.rs`, `ops/trig.rs`, `transcend_impl.rs`; root `fma_special_cases` and `decompose` against siblings `handle_specials` and inline decode; root `ops/nan_propagate.rs` with no sibling module; `PRECISION` defined twice per crate (`bid.rs` as `u32`, `digits.rs` as `usize`); `U128_DIGIT_CAP = 38` defined eight times (d64 and d32 addsub, fma, divide_integer, rem). Each costs a grep miss when a fix is ported; C4-9 and C4-10 are fixes that did not get ported.
5. **Status vocabulary in `ferrodec-decimal`**: `Rounding` and `RoundingMode` should be one type with a fallible narrowing to the IEEE five (C4-14); the crate is pre publication, so this is the cheapest moment.
