### C3-1: the Newton copies (trio drift, quantified)

Evidence: `git log -L '/pub fn recip/,/^    }/:ferrodec-transcend/src/extended.rs'` returns only 4479043 (2026-05-17, the move into the crate). The same query on extended2.rs returns only a074259 (2026-07-31). On extended_dyn.rs it returns only 4422333 (2026-08-01), and `newton_steps` (extended_dyn.rs:1167-1176) is from that same commit. The fixed rung loops are extended.rs:786 and :823 (`0..2`) and extended2.rs:654 and :683 (`0..3`). Bead fd-k9t ("derived step counts in extended.rs/extended2.rs") has been open at P2 since 2026-08-06. extended2.rs:23-24 and extended_dyn.rs:44-48 both state "Any behavioral divergence ... beyond width parameters is a defect", so by the files' own rule the divergence is a defect, and it has been known for two months.

What the shape costs, measured in this wave's terms. The Newton seed class (fd-0o9, fd-h3jk, A4-6, A5-6) lives in all three copies, so its closure needs six edits (recip and sqrt in each of three files). The one copy that derived the step count did so from `F::PRECISION`, which still undercounts on a subnormal seed (A3-1's mechanism; see C3-7). The single fix that exists never propagated (fd-k9t).

The repair costs nothing. `recip` and `sqrt` use only `to_format`, `from_format`, `from_i32`, `mul`, `sub`, `add`, `div`, `half`, and `F::recip_seed`/`sqrt_seed`, all of which are `ExtNum` members (extended.rs:937-1145), so one generic function monomorphizes to today's code on the fixed rungs. The same holds for `div`, `sub`, `square`, the three predicate wrappers, `is_zero`, `neg` and `abs` (similarity 1.00 after normalization; trio table below). The trio table also records three more behavioural divergences, beyond the step count, in failure modes:

- `boundary_verdict`'s kept coefficient: the fixed rungs use `debug_assert` plus silent low limb truncation (extended.rs:621-622, extended2.rs:499-504), while the dynamic rung panics through `expect` (extended_dyn.rs:1066-1068).
- `trunc_to_i32`: the fixed rungs wrap silently (extended.rs:1321, :1332; extended2.rs:736-740), while the dynamic rung panics (extended_dyn.rs:833-855, documented there as deliberate).
- `add`'s capacity cut: `115u32` (an unnamed literal, extended.rs:705) against `U768_DIGIT_CAPACITY` (231) against `2·prec + 11`; the slack differs (15 against 11), which extended_dyn.rs:77-88 documents.

What one implementation of the remaining bodies needs (`add`, `mul`, `div_u32`, `cmp_abs`, `boundary_verdict`, the rounding helpers): a coefficient trait over `U256`/`U384`/`DecBig` with `mul_pow10`, `div_rem_pow10`, `decimal_digit_count`, `cmp`, `sub`, and an associated double width product type. The dynamic rung takes `&self`, so the trait would be by reference with `Copy` fixed width impls. On the fixed rungs this is zero runtime cost under monomorphization; the cost is compile time plus one M4 style byte identity gate. A const generic over limb count does not fit, because the multiword substrate exposes `U256`/`U384`/`U768` as distinct types. Not prototyped (Least sure).

## Design notes

1. **Kernel bodies as a typed pipeline.** The shape is special table → exact/tie classifier → anchor arms → core → guarded delivery. Five functions over 80 lines mix all five stages: atan2_kernel_body (87 lines), atan2_pi_kernel_body (106), hypot_kernel_body (116), sincospi_kernel_body (118) and rootn_kernel_body (101). Those that are long because the algorithm is long are `boundary_verdict` ×3 (93 to 123), `reduce_dyn` (130), `reduce_body` (100), `pow_special_cases`/`powr_special_cases` (100/103, tables) and `pow_exact_input` (88). The sibling bodies hold different anchor sets for the same core: atan2 has none (inverse_trig.rs:403-418, fd-gu75), atan2_pi has two gap arms (inverse_trig_pi.rs:478-500). Separately, ladder.rs:44-131 is a twelve item prose list of deliveries that bypass the guard. A per function anchor table, plus a delivery enum, would make an omitted arm a compile or test time fact. Evidence that would make it a finding: a second missing arm (A3-H1 is the candidate).
2. **Split exact.rs along the seams it already marks.** The file has eight `// ----` sections: :345 exp2/log, :1200 cbrt, :1283 pow, :1483 rsqrt, :1680 powi, :1874 rootn, :2081 compound and quanta, :2650 hypot. Five retired test only predicates are interleaved at :127-344. The only exact.rs item any `trig-pi` module uses is `strip_trailing_zeros` (exact_pi.rs ×6), so `mod exact` (3,800 lines) is compiled under `trig-pi` for one 20 line helper. That is A1-1's structural cause. Also unify `pack_value` (exact.rs:389) and hypot's identical `pack_exact` (hypot.rs:285); routing A2-1's special rows through that one packer is A2 note 2.
3. **Totality where prose carries the precondition.** The candidates are `from_format` (C3-8), `trunc_to_i32` (ExtNum doc at extended.rs:1076-1078; return `Option<i32>`), `parse_str` (const built constants), and `run`'s `rung2: FnOnce() -> Option` (ladder.rs:525-532: a top rung that "delivers unconditionally" could have a type returning `(F, Status)`).
4. **One gate table per (function, format).** The current `DecimalFormat` vocabulary names only `exp`'s gates (format.rs:156-176), and sinh, cosh and the expm1 family borrow them (exp.rs:266, hyperbolic.rs:172, :221). A5 note 2 already proposes the table; the structural point here is that the seam has no word for a non `exp` gate.
5. **Rung names.** A reader of ladder.rs learns `round_guarded`, `round_adjudicated`, `rung_budget` and `Budget.{rung1, rung2, dynamic}` from their names. `run` against `run3` (run3 runs every rung, and the "3" is rung 3's entry) and `ESCALATES` (a `const` whose value for `Extended2` depends on the build's features) need the ADR. Renaming `run3` to `run_with_ziv`, and documenting `ESCALATES` as build dependent at its declaration, would make the model readable from the file plus C3-12's glossary.
