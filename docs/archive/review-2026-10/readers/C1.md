## Per-finding evidence

### C1-1 (P1, reproduced)

**Reproducer.** `{{SCRATCH}}/C1/oracle_repro/`, a cargo project with path deps on `ferrodec` (transcendentals) and `ferrodec-test-support` (feature `transcend-oracle`), Cargo.lock copied from the repo. It implements `FaithfulFormat` for a Decimal128 newtype exactly as `tests/common/mod.rs:72` does, and calls the public `within_faithful_ulp` / `faithful_side_ok`. Command:

`CARGO_TARGET_DIR={{SCRATCH}}/target-C1-repro cargo run --offline -q --bin oracle_repro`

Output (excerpt):
```
A tiny: true=1e-400 got=7e-400                                    faithful=true side_ok(TowardPositive)=true
A tiny: true=1e-400 got=9.999999999999999999999999999999999e-301  faithful=true side_ok(TowardPositive)=true
A tiny: true=1e-400 got=0                                         faithful=true side_ok(TowardPositive)=true
B anchor: true=1+1e-50 got=1 rm=TowardPositive side_ok=true
D sweep: true=1.0000000000000000000000000000000005 got=1 rm=TowardPositive side_ok=true
E exp(1): got=exp(1) - 2ulp  faithful=true side_ok(TowardPositive)=true
E exp(1): got=0              faithful=true side_ok(TowardPositive)=true
E exp(1): got=-7             faithful=true side_ok(TowardPositive)=true
E exp(1): got=exp(1)+2ulp    faithful=false side_ok(TowardPositive)=false
F sin(-1): got=sin(-1)-2ulp   faithful=true
F sin(-1): got=sin(-1)+2ulp   faithful=false
F sin(-1): got=-5             faithful=true
```

**Root cause.** `--bin abscmp` in the same project prints, among others:
```
abs_cmp(-5e-34,1e-40)=Some(-1)
abs_cmp(2,-3)=Some(1)
abs_cmp(-3,2)=Some(-1)
```
These are signed results. The source confirms it: `~/.cargo/registry/src/*/astro-float-num-0.3.6/src/ext.rs:352-355` documents "Compares the absolute value of self to the absolute value of d2" but returns `v1.cmp(v2)`. Cargo.lock pins astro-float 0.9.5 and astro-float-num 0.3.6; 0.3.7 is identical.

**Trace.**
- `cmp_approx` (transcend_oracle.rs:172-187): for `a < b`, `diff` is negative and `diff.abs_cmp(&tol) <= 0` holds, so the function returns `Equal`. It therefore never returns `Less`.
- `within_faithful_ulp` (:193-203): the `next_up < true` arm can never fire.
- `faithful_side_ok` (:283-292): `side == Equal` returns true for every mode.
- `assert_faithful` (:364-371): treats a low result as "exact" and skips the INEXACT check.
- :177: for a negative oracle, `tol` is negative, so it is replaced by 1e-300. For a positive `|true| < 1e-260`, the 1e-300 floor swallows the `Greater` side too (case A).

`within_n_ulp_band` (:243-260) and `ulp_at` are unaffected because they take `.abs()` first. The ADR-0025 metamorphic layer is sound on this axis.

**Blast radius.** Every `assert_faithful` consumer is affected: root `tests/property_{exp,ln,pow,sincos,sincos_large,hyperbolic,inverse_trig,derived_transc,exp10,exp10_m1,powi,log10_1p}.rs` and the d64/d32 `property_*` lists (see `grep -l assert_faithful`). They are outside C1's file scope and are handed to Waves 2 and 3. The layer catches high-side errors only: TowardNegative misrounds and too-large nearest results. It cannot catch TowardPositive misrounds, too-small results of any size, or TowardZero misrounds of negative results. The June report's "a 1 ULP directed misround passes by construction" understates this: half of all errors of any magnitude pass.

**Why the stack missed it.** The instrument has no negative-control self-test. Nothing in ferrodec-test-support asserts that a known-wrong value is rejected; every consumer only ever feeds it correct kernel output, so a check that accepts too much stays green forever. The second cause is upstream doc text: the `abs_cmp` name and doc promise absolute comparison. ADR-0021 and testing.md layer 3 describe the bracket as "exact" within its magnitude domain; that is map, not territory. No wrong shipped value is witnessed. The frozen corpora (exact equality, independent of astro-float) bound the damage wherever they have rows; C1-5 names where they do not.

## Design notes

1. **ferrodec-test-support needs a self-test tier.** Every oracle or harness (transcend_oracle, differential, frozen loaders) should carry negative controls that must be rejected. C1-1 and C1-4 are both "the instrument accepts too much" and are invisible to any consumer-side test. Evidence that would make this a finding: none beyond C1-1 itself.
2. **The kernel-dispatch `match` is copied six times** (transcend_vectors, planted, ladder_telemetry, campaign_s2, anchor_bands, times three crates), each with its own subset (planted lacks rsqrt/hypot/cbrt; campaign has 9 ops). One `dispatch(func, x, y, n, rm)` per crate in `tests/common` would remove drift. It becomes a finding if a corpus file arrives that one copy maps differently.
3. **Corpus integrity should hash whole directories** (`verify_all` minus the manifest), so `.prov`, `.tsv` and `MANIFEST.json` cannot fall outside the attestation by extension (C1-19).
4. **The mode coverage of each corpus should be a pinned matrix** (function × precision × mode × corpus), asserted by one test, so that "NearestEven-only" (C1-5) is a visible, deliberate table entry rather than an absence.
5. **mock_format should become a real rounding double**, or the inline suite should state in its crate doc that delivery and specials are tested only in the integration suites. C1-11, C1-13 and the T4 class all stem from it.
