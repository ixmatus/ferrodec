All five modes for the first witness: ferrodec NE `…006`, NA `…006`, TZ `…005`, TP `…006`, TN `…005`; libmpdec NE `…005`, NA `…005`, TZ `…005`, TP `…006`, TN `…005`. Exact values (libmpdec at prec 200): `7500000000000005499999999999999.99999999`; for the third witness `25000000000000009999999999999999.5`. The random structured differential (`b2diff 3000000`) found 10 such mismatches in 15,000,000 d64 fma cases (NE, NA, TZ, TP, TN all represented), zero in 15,000,000 d32 fma cases.

Trace (first witness): `fma` (fma.rs:151) takes `ab_coef = 7500000000000005500000000000001` (31 digits, `ab_exp = 0`), `c = 100000001E-8` (9 digits). `target_q = -8`, `shift_ab = 8 > ab_safe_shift = 7`, so the exact path (fma.rs:255) is skipped. `ab_top = 30`, `c_top = 0`, gap 30 < `WORK_DIGITS = 32`, so the sub-ULP path (fma.rs:288) is skipped too and the overlap path runs: `q_work = max(-8, 30 - 31) = -1` (line 332); `align_to_quantum(c)` truncates `100000001E-8` to `10E-1` with `c_st = true` (lines 132-148, 334); `ab` aligned to `q_work` is `75000000000000055000000000000010E-1` and the truncated `c` is `10E-1`, so the effective difference is `75000000000000055000000000000000E-1` (32 digits), whose 16 digit cut sits exactly on the tie `7500000000000005|5000000000000000`; `pre_sticky = true` (line 335) is then read by the rounder as "the true value lies above", so NearestEven rounds the apparent tie up. The true value lies below: the truncated digits belonged to the subtrahend. The doc at fma.rs:126-131 ("every dropped digit is provably below the rounding position and collapses correctly into the sticky bit") is true for magnitude but false for direction on effective subtraction; the sub-ULP path above it already handles the direction with `h2_borrow_and_extend` (fma.rs:71-81), the overlap path added under fd-9fi (commit 7655b7c) does not. The witnesses were derived by hand from this mechanism (choose `a·b ≡ 5·10^14 + 1 mod 10^15` with 31 digits and a 9 digit `c = −(1 + 10^-8)`), and the prediction held, which is the falsification test of the trace.

Why Decimal32 is clean: the overlap path is unreachable there. For the higher exponent side X, `shift = (tX − tY) + dY − dX ≤ 13 + 14 − dX < 38 − dX` whenever the tops are within `WORK_DIGITS = 14`, so the exact path always wins (d32 fma.rs:143, 323, 364). At d64 the product has up to 32 digits and the same inequality fails for `dY > 7`.

Why the stack missed it: trust table rows "property_fma_oracle ×3" (uniform `arbitrary_finite` coefficients; the overlap path needs the 16 guard digits of the difference to sit exactly on a boundary, probability about 1e-16 per draw) and "regression_*" (fd-9fi pinned the overlap example `fma(9.007199254740992e+19, …)` on effective addition only). ddFMA has no vector of this shape (1,311 pins pass). C2's sibling differential (180,000 edge biased cases plus the 43,830 case power of ten family) has no `k·10^15 + 1` coefficients. Kani is special only.

Tables and constants (checklist 2): every `POW10_*` table in both siblings indexed against its maximal reachable index by reading (d64 div.rs:14 [34] max 32; sqrt.rs:15 [34] max 33; quantum.rs:34 [16] max 15; round.rs:27 [20]; d32 div.rs:26 [16] max 14 with the u64 product bounded by 10^15; d32 quantum.rs:24 [10] max 6); `KEEP` (19 and 14), `U128_DIGIT_CAP` 38, `WORK_DIGITS`, BID field constants, `COEFFICIENT_FIELD_LIMIT` (2^53 + 2^51 and 2^23 + 2^21), `MAX_CANONICAL_NAN_PAYLOAD` (10^15, 10^6), `SCALEB_N_LIMIT` (800, 206). Public constants pinned by value (`consts`): ZERO, NEG_ZERO, ONE, NEG_ONE, TEN (`10E0`), MAX `9999999999999999E369` / `9999999E90`, MIN, MIN_POSITIVE `1E-398` / `1E-101`, MIN_POSITIVE_NORMAL `1E-383` / `1E-95`, the NaNs and infinities, all canonical. `pi`, `e`, `ln2`, `ln10` (`mconst`) equal mpmath rounded to 16 and 7 digits. No June `POW10_U64` class defect remains.

Panic hotspots (checklist 7): d64 quantum.rs (21 non-test sites) and rem.rs (19), d32 quantum.rs (15) and rem.rs (18) read; each `expect` rests on a `classify_bits` invariant or a bound checked a few lines earlier. The one non-obvious bound, rem_near's `result_mag < 10^p` after the trailing zero loop (d64 rem.rs:319-334), holds by derivation: with `n ≥ 1`, `|r| ≤ |b|/2 ≤ |a| < 10^p·10^(ea)`; with `n = 0`, `r = a`; on the `eb < ea` side `|r| ≤ |b|/2 < 10^p·10^(eb)`. No panic in roughly 100 million debug assertion enabled calls. Blind spot: `next_up`/`next_down`/`logb` only via the 17 value probe.

Special value dispatch (checklist 4): the full three format probe (14,331 rows per format) found no other divergence than the rows in the dispatch table below; in particular add, sub, mul, div, fma, quantize, rem_near, rem_trunc, divide_integer, next_toward, partial_cmp, compare_signaling, total_cmp, same_quantum, compound, rootn, powi and every unary NaN/Inf row agree on all three.

Divergence classification (checklist 1): see the extra deliverable. Method: `hunks.py` splits every mirror diff into hunks, marks a hunk `test` past the left file's `#[cfg(test)]`, `doc` if only comment lines change, `width` if the code lines are equal after normalizing integer widths, literals and `POW10_*` names, and prints the residue, which I read. Blind spot: a whole file rewrite (root versus sibling addsub, div, fma, mul, rem, sqrt) is one hunk; for those the classification rests on the differential, not on the diff.

## Design notes

1. One special value dispatcher per format pair is overdue: B2-2, B2-3, B2-4, B2-5 and the four known rows (C2-2, C2-3, C2-4, A5-4/5) are eleven independent copies of "NaN first, then this function's table". The evidence that would make it a finding is already here: the probe's divergence list is entirely in hand written per crate dispatch, none in the shared kernels' tables.
2. The d64 fma has three alignment paths (exact, sub-ULP, overlap) and only two carry the effective subtraction direction fix; a single "align with directed residue" helper used by all paths (and by addsub) would make B2-1's class unrepresentable. The d32 overlap path is dead code by the inequality in B2-1's evidence; a const assertion would document that.
3. The siblings' width parameterization is partly derived and partly literal (B2-10); a `const` table generated from `PRECISION` (as `POW10_U128` already is in fma.rs) for every table would let one const assertion per table carry the June class.
4. The three format probe (`$SCRATCH/B2/nanp`) is a cheap durable instrument: 17 operands, every operation, diffed across formats. Checked in as a test with an allow list of the width rows (shift/rotate past 7 digits on d32), it would have caught every row in the dispatch table.
5. The `DecimalFormat` trait's NaN contract (format.rs:98) and the root's implementation disagree; the trait is the right home for the rule, with one shared implementation over `classify`.
