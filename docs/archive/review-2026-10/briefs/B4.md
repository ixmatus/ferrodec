# Reader B4: `ferrodec-decimal`, the arbitrary precision crate (Wave 3)

Lens: correctness under a user chosen `Context` (precision, exponent
range, rounding), including the extremes the type system admits, and
the contract of every path that can decline to be correctly rounded.

## Scope (yours alone in this wave)

- `ferrodec-decimal/src/**` (about 6,500 lines: `arith`, `classify`,
  `compare`, `context`, `convert/`, `decimal`, `digits`, `divrem`,
  `exponent`, `from_float`, `interop`, `logical`, `next`,
  `positioning`, `quantize`, `round`, `sqrt`, `to_float`, and
  `transc/{consts,exp,ln,mod,pow,series,strategy,work}.rs`).
- `ferrodec-decimal/tests/conformance.rs` only for the 99 skipped
  vectors and the `power` tolerance (C2 read the runner).

Governing: GDA (the General Decimal Arithmetic specification and its
decTest files under `ferrodec-decimal/tests/vectors/`), ADR-0038
(differential is king), ADR-0039/0040 (the transcendental surface and
the bounded Ziv with its named residual), ADR-0042 to 0046 (1.0 and
the `DecBig` performance arc), ADR-0053 (exponent gap guards),
ADR-0054 (`NonZeroU32` precision), ADR-0055/0056 (`to_f64`),
`wave1-verification.md` D3-6 and the `arith.rs:248` lead.

## Checklist

1. **`DecBig` normal form.** `from_ascii_digits` guards normal form
   with a `debug_assert` only (June): which public paths can build a
   non normal `DecBig` in release (leading zero limbs, a zero with a
   nonzero digit count) and what consumes it (B5 owns the type's
   internals; you own the crate's use of it).
2. **ADR-0053 exponent gap guards, every path.** Operands whose
   exponents differ by `10^6` to `10^9` through `add`, `sub`,
   `compare`, `fma`, `quantize`, `rem`, `divide_integer`,
   `next_toward`, `sqrt` and the transcendental functions: does any
   path materialise `10^gap` (time, memory), and is the result
   correct (CPython `decimal` with the same context is the oracle;
   it has the same guard problem, so construct the expected value
   analytically where it stalls). Table: path, guard, test that
   pins it, or "none".
3. **`arith.rs:248`** `u32::try_from(...).expect(...)`: reproduce the
   panic at precision `u32::MAX` with a one digit operand (legal
   under `NonZeroU32`), find every sibling site that converts a
   precision or digit count into `u32`/`usize`, and state the
   closure (a documented maximum on `Context`, or saturation).
4. **Exponent arithmetic at the context's extremes.** `Context`'s
   `emax`/`emin` types and ranges; `i128` cohort arithmetic in
   `quantize`, `scaleb`, `logb`, `exponent.rs`; the clamp and
   CLAMPED semantics under GDA's `clamp=1`; subnormal results and
   the `etiny` rule; overflow and underflow with every GDA rounding
   mode including `ROUND_05UP` if the crate has it (if not, say so
   and whether the docs claim GDA completeness).
5. **Panic sites.** `arith.rs` (16 panic, unreachable, expect or
   unwrap sites) and the crate's 60 `expect(` calls: reachability
   from the public API with legal `Context` and operands (C4 owns
   the clarity cost; you own reachability).
6. **`interop`, `from_float`, `to_float`.** Conversions to and from
   the fixed formats and `f64`: cohort, flags, signaling NaN
   handling; `to_f64` sets INEXACT unconditionally with a false doc
   premise (D3-6, confirmed): reproduce and extend to `from_f64`
   exactness and `to_f32` if present.
7. **The 99 skipped GDA vectors.** Each by class with the reason the
   runner gives and whether the reason is true of the code today;
   the `power within 1 ulp` tolerance (C2 trust table): is `power`
   correctly rounded or faithful under the crate's own docs, and is
   the tolerance hiding a last ulp defect (replay the `power` rows
   exactly).
8. **`transc/strategy.rs`, the seeded hypothesis (P1 if true).** The
   bounded Ziv re-runs at a growing guard until the bracket test is
   decisive and, at the cap (`8 · 2^11` doublings), returns through
   `faithful_round` with the same `(Decimal, Status)` shape as a
   decided result. Read the contract (`lib.rs`, ADR-0040's "named
   residual") and answer: (a) is the cap reachable from the public
   API, in particular by inputs whose true result is exactly
   representable or exactly a midpoint at the context precision
   (`exp(0)`, `ln(1)`, `pow(10, 2)`, `pow(2, 10)`, `pow(4, 0.5)`,
   `pow(x, 1)`, `pow(x, 0)`, `exp10` of integers if present), where
   a bracket never becomes decisive; (b) if an exact detection path
   exists, which inputs it misses; (c) what the wall time is on the
   way to the cap (each doubling costs; `2^11` doublings from a
   small guard is astronomically wide: measure the first several and
   state whether an attacker supplied input can make a call run for
   minutes, which is a P0 class on untrusted input); (d) whether a
   caller can distinguish the faithful fallback from a decided
   result at all. Reproduce whatever you claim.
9. **`transc/{exp,ln,pow}.rs`** (changed since June): the argument
   reduction and error bound at precision `p` as a function of `p`
   (the guard digits added, the series termination, the constants'
   depth from `bigconst` against the requested `p`); probe at
   `p` = 7, 16, 34, 100, 1,000 and 10,000 against mpmath with
   matching `dps` and every rounding mode the crate offers; report
   the deepest precision you exercised and the time per call.
10. **Differential.** CPython `decimal` with the same context for the
    arithmetic (all GDA modes, several precisions including 1 and 2,
    structured operands as B1's) and mpmath for the transcendentals;
    counts per operation.
