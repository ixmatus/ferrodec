# Reader D3: ADR coherence (Wave 1)

Lens: does the code do what each architecture decision record says
was decided, is each risk an ADR named still open or closed, and are
decisions that shape the code recorded at all? The ADR log is the
durable rationale a 2040 maintainer reconstructs intent from; drift
between it and the tree is a defect in the record.

## Scope (you own these)

- ADR-0050 through ADR-0061 in full (`docs/decisions/005*.md`,
  `006*.md`).
- Ten earlier ADRs chosen by citation density in production source
  (from `docs/archive/review-2026-10/adr_density.md`): ADR-0016 (142
  citations), 0032 (30), 0033 (28), 0031 (27), 0027 (23), 0014 (18),
  0029 (15), 0026 (14), 0048 (12), 0024 (12).
- `docs/decisions/README.md` (the index) and `template.md`.
- Every plan under `docs/decisions/plans/` (17 files): the status
  line of each.
- The `Related` and status fields of all 61 ADRs (a cheap sweep for
  propagation).

You read code only to decide whether an ADR's Decision matches it;
defects you notice along the way go to "least sure" as leads for
the Wave 2 and 3 readers.

## Checklist

1. **Decision versus code.** For each ADR in scope: restate the
   Decision in one sentence, then cite the file and line where the
   code does it (or does not). A Decision the code no longer follows
   is a finding (severity P3 if the ADR should be marked superseded,
   P2 if the code silently diverged, P1 if the ADR's claim about
   correctness no longer holds).
2. **Named risks.** Each ADR's Consequences, open questions, and
   landing addenda name risks. For each: still open, closed (by what
   commit or ADR), or silently abandoned (no record either way). Known
   ones to settle: ADR-0050 "re-running the exhaustive d32 kernel
   verification is left open"; ADR-0053 prose only bracketing
   argument; ADR-0057 per crate copies of the saturation sentinel can
   drift; ADR-0059 "model" and "argued, not proved" claims, fd-k9t,
   the S5 specialist verification, the S2 cloud tiers; ADR-0060 "Not
   specialist verified" banner; ADR-0061 "no CI lane builds each
   feature alone" (fd-z26).
3. **Status propagation.** Superseded (0006 by 0007, 0017 by 0018,
   0024 by 0032, 0045 by 0055) and amended (0032 by 0050 and 0059,
   0033 by 0050, 0047 by fd-aqs.8) marks present on BOTH sides? Does
   any ADR's status line disagree with its Related block?
4. **The index.** `docs/decisions/README.md` stops at 0054; ADR-0055
   to 0061 are missing. Anything else in the index that disagrees
   with the files (titles, statuses)?
5. **Unrecorded decisions.** Decisions that shape the code but live
   only in a CHANGELOG entry, a commit message, a plan file, or
   nowhere: the version tag naming change from `ferrodec-vX` to `vX`
   at 4.1.0; the `telemetry` test only feature being public; the
   three sibling crates' continued existence as hand mirrored copies
   (ADR-0011 is the last word; is its rationale restated anywhere
   since the drift?); the choice to float the toolchain on stable
   (Phase 0 recorded it in `rust-toolchain.toml`; is that enough?).
   Name each with where it is currently recorded and whether it
   deserves an ADR.
6. **Plans.** Each plan file's status line: executed, superseded,
   abandoned, or still open? A plan marked "proposed" whose work
   landed is a stale record.
7. **ADR claims that are also README claims.** Where an ADR's
   correctness claim (correctly rounded; exhaustively verified;
   proven; unconditional) is repeated in README.md or testing.md,
   note the pair for D2 (who owns the README side).

## Deliverable in addition to the schema

An **ADR status table**: ADR; decision in one sentence; code
location that implements it; match (yes, partial, no); named risks
and their state. And a **propagation list** of every status or
Related mark that is missing on one side.
