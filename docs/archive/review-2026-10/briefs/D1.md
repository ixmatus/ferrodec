# Reader D1: architecture across the workspace (Wave 4)

Lens: architectural correctness, verified not argued. Feature graphs
are built, not read; `no_std` claims are compiled for the target; API
consistency is tabulated; the type level invariants are listed against
the runtime checks that stand in for them. The ADR-0011 judgment (one
generic crate or three) is the coordinator's synthesis over the Wave 3
verdicts and your facts, and a decision for Parnell; you supply the
facts.

## Scope (yours alone in this wave)

- Every `Cargo.toml` in the workspace, `rust-toolchain.toml`,
  `.cargo/config*`, the `[features]` and `[workspace.lints]` tables;
  every `#[cfg(feature = ...)]` and `--cfg` lane (`force_escalate`,
  `force_adjudicate`, `force_rung3`, `ladder_audit`, `telemetry`).
- The public API surface of the three format crates (`pub` items and
  their signatures; `cargo public-api` if installed, otherwise
  `cargo doc --document-private-items` plus grep), `ferrodec-decimal`,
  `ferrodec-transcend`, `ferrodec-multiword`, `ferrodec-ieee`.
- `ferrodec-transcend/src/format.rs` (the `DecimalFormat` seam).

Governing: ADR-0011, ADR-0029 (the 2.0 breaking set), ADR-0057 (per
crate sentinel), ADR-0059 §"features", ADR-0061 (narrow feature CI
blind spot), the plan's D1 row, `wave1-verification.md` D3-15 and
D3-16, `wave2-verification.md` "Handed to Waves 3 and 4" (D1 items),
`wave3-verification.md`.

## Checklist

1. **The feature graph, built.** Per crate, per feature singly and in
   the documented combinations:
   `cargo build --target thumbv6m-none-eabi --no-default-features
   --features <X>` and `cargo clippy -p <crate> --no-default-features
   --features <X> -- -D warnings`, with the log. Known: `trig-pi` alone
   compiles 46 dead items in `exact.rs` (A1-1) and `exp-log` alone 8;
   the siblings imply `binary-float` where the root does not (D3
   lead); `unbounded-ladder` pulls `alloc`; `telemetry` is a public
   feature whose counters are test only (D3-15, A4-4); `thumbv8m` is in
   the toolchain file but never built (C5). This is also the fd-z26
   residue check. Table: crate, feature set, target, build, clippy.
2. **`no_std` and `alloc` posture per crate.** What each crate needs
   at default features, with `alloc`, with `std`; any `std` leakage;
   `#![no_std]` with `extern crate alloc` boundaries; the
   `ferrodec-decimal` crate's requirement set.
3. **Public API consistency across the three formats.** One table of
   every public method: present on root, d64, d32 (name, signature
   shape, `Status` semantics, preferred exponent behaviour, operator
   default rounding). Known asymmetries: the d32 removal of
   `ExponentOutOfRange`; `pow(sNaN, ±0)` three ways (A5-5); sibling
   `min`/`max` payload (C2-4); the wrapper docs' tiers (B2). B2's
   divergence table is your input for behaviour; you own the surface.
4. **Type level invariants versus runtime checks.** Canonical
   encodings (`from_bits` accepts non canonical; where is canonical
   guaranteed), `NonZeroU32` precision with `arith.rs:248` (B4),
   `Status` as a set, `RoundingMode` as an enum used through
   `for_negation`, the Newton primitives' operand range as a prose
   precondition (A5-6), `mantissa_bits` as `u32` (B5-5), budget units
   as bare `u128` (A3), `Extended::parse_str` and `recip`/`sqrt`
   public on a published crate (A3-9, A5-6). For each: the runtime
   check or comment that stands in, and the type that would replace
   it.
5. **The `DecimalFormat` seam** (`format.rs`): what the trait
   promises, what each format supplies (`format_impl.rs`,
   `transcend_impl.rs`), whether the gate constants belong on the
   trait or in a derived table (A5 design note 2), and whether
   `mock_format.rs` implements it faithfully (C1-11).
6. **Dependency hygiene.** Every dependency and dev dependency per
   crate with its reason; `astro-float` (one sided `abs_cmp`, C1-1) as
   an oracle dependency; `serde`, `num-traits` optional and gated;
   MSRV `1.84` checked for the root only (`cargo msrv` or a pinned
   toolchain build for every crate); `Cargo.lock` tracked.
7. **`pub` that should be `pub(crate)`.** `ferrodec-transcend`'s
   public surface is consumed only by the three format crates: list
   the `pub` items no format crate uses; the semver exposure of the
   `--cfg` lanes (do any change public behaviour).
8. **Build and test selection parity.** After Phase 0 the battery has
   14 lanes; `ci.yml` and `verification.yml` select differently (C5):
   the multiword tests run without `--all-features` in some lane so
   none of the `DecBig` tests run (coordinator's pin probe); list each
   (lane, crate, features) triple and what it misses.
9. **The three crate question, facts only.** Line counts, mirror diff
   sizes (`mirror_summary.md`), the B2 divergence classes, the fixes
   that landed in one crate only (C4 collects `git log -L` receipts),
   the per crate constants and sentinels, the compile time and binary
   size of each crate on thumbv6m, and what a generic
   `Decimal<const P, const EMAX>` would need from the current code.
   No verdict; the coordinator synthesises.

## Extra deliverable

The feature matrix (crate × feature × target → build, clippy), the
API consistency table, and the invariant table (invariant, current
mechanism, type that would carry it).
