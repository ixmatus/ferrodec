## Checklist

1. **The exact oracle under a correctness lens.** `oracle.rs` is the
   reference every add/sub/mul/div/fma/sqrt/quantize/rem claim is
   checked against. Re-derive its rounding at all five modes on
   constructed cases against `fractions.Fraction`: ties at every
   mode, results that land in the subnormal range, results needing
   CLAMPED (ADR-0048), zero results with sign, overflow to the
   format maximum under directed modes, the preferred exponent
   (§6.3). Then read `oracle_soundness.rs`: what does it prove about
   the oracle, and what would a wrong oracle still pass?
2. **Kani harnesses.** For each harness file: vacuous `assume`
   (an assume that excludes the interesting inputs, or an assume
   contradicting another so the harness proves nothing); `cover!`
   where `assert!` was meant (June found non binding `cover!(false)`
   arms in `src/verify/encode.rs`); whether the ADR-0016 shim
   routing exercises the production code path or a parallel
   simplified one; what each harness actually proves, in one line.
   The harness counts come from `docs/archive/review-2026-10/counts.md`;
   do not recount, and do not adjudicate the README claim (D2 does).
3. **Conformance runners.** For each `conformance.rs`: the
   `expected_per_file` pins are exact per file (pass, skip,
   fail)? Every skip class is justified in prose at the runner, and
   the justification is still true? The June `strip_comment` defect
   (`--` inside quoted operands dropped six vectors): fixed and
   tested? Which decTest directives (precision, rounding, clamp,
   extended, maxExponent) does the runner honor and which does it
   silently ignore?
4. **Regression tests.** Each `regression_*` file: pinned to the
   fixed value with the original failing input, or re-derived from
   live behavior (which would pass a reintroduced bug)?
5. **Property tests.** Strategy ranges versus the claim in the test
   name; shrinking disabled anywhere; `proptest!` blocks whose
   assertion is weaker than the doc comment above them.
6. **Multiword's coverage gap.** 122 test lines for 4,210 source
   lines: which of `U256..U1024` operations have no direct test at
   all (June: Algorithm D's add back branch had zero coverage; is
   that still so?), and what does `decbig.rs` leave unexercised?
7. **Integrity tests.** `vendored_integrity.rs` and
   `corpus_integrity.rs` delegate to `vendored.rs`: does every vector
   directory have sums, and is every directory covered (the s1
   campaign corpus is absent from `corpus_integrity.rs`;
   `ferrodec-campaign/tests/vectors/margin_lockstep.txt` has no sums)?
8. **`identity_exhaustive.rs`.** The README claims an exhaustive
   2^32 sweep with zero violations; what does the ignored test
   actually sweep, and when did it last run (git log)?
