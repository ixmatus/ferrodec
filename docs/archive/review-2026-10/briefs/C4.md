# Reader C4: clarity and pragmatism, the format crates and substrates (Wave 4)

Lens: principled engineering. Clear, pragmatic, well written code whose
structure earns its keep; comments that say what the code does; examples
and benches that demonstrate what they claim. The correctness readers
(B1 to B5, Wave 3) have judged values; their reports under
`readers/B*.md` and the verdicts in `wave3-verification.md` are your
inputs.

## Scope (yours alone in this wave)

- Root `ferrodec` `src/**` less `src/math/` (C3 reads the shims) and
  `src/verify/` (C2 read the harnesses): 20,678 lines.
- `ferrodec-decimal64/src/**`, `ferrodec-decimal32/src/**` (18,622 and
  19,666 lines), `ferrodec-decimal/src/**` (7,037), `ferrodec-multiword`
  (4,218), `ferrodec-ieee` (920).
- `examples/*` and `benches/*` in every crate.

Governing: the workspace lint policy (`[workspace.lints]` in the root
`Cargo.toml`: 24 allowed pedantic lints), ADR-0011 (three crates),
ADR-0043 (`DecBig` performance rationale), the Wave 3 design notes,
`counts.md` (per crate `as` casts, `unwrap`, `expect`, `panic!`,
`unreachable!` in production source: d32 21 `unwrap`, d64 49 `expect`,
decimal 60 `expect`).

## Checklist

1. **The large functions.** `add_inner` (about 215 lines),
   `parse_str_inner` (210, three copies), `fma` (205), `quantize`
   (183), `finalise_finite` (167) and every other function over 120
   lines in scope: long because the algorithm is, or because concerns
   mix; where mixing, name the seams.
2. **The workspace clippy allow list.** Each of the 24 allowed
   pedantic lints: the number of sites it silences per crate (enable it
   in a scratch copy, count), and whether the allow earns its place
   (a real false positive family) or hides debt (the cast lints: 372 +
   311 + 329 + 94 + 110 `as` casts with no bound comment).
3. **Mirror drift as maintenance cost, with receipts.** From the Wave
   3 B2 divergence table and `mirror_summary.md`: concrete cases where
   a fix landed in one format and not another (`git log -L` on the
   twin functions), the per crate copies of the saturation sentinel
   (ADR-0057), the three `pow_special_cases` with three behaviours
   (A5-4, A5-5, C2-3). This is evidence for D1's ADR-0011 synthesis,
   not a verdict.
4. **Comment accuracy.** Every comment Wave 3 marked false (B2's
   wrapper docs, B5-6's merged doc, B5-7's clause citation, the
   `format_impl.rs` gate comments) as a class; sample sixty comments
   that state a number, a bound or a clause and check each against
   the code.
5. **`expect(` and `unwrap` density.** `ferrodec-decimal` 60
   `expect(`, d64 49, d32 48 and 21 `unwrap`: for each, is the message
   a proof (names the invariant that makes the `None` impossible) or a
   hope; group by shape and propose the type level fix where one
   exists (B5-5's `mantissa_bits` enum, B4's `arith.rs:248`
   precision bound).
6. **Dead and vestigial code.** Items kept for an ADR that was later
   amended (ADR-0027's `rem` story, D3-4), `cfg` gated items with no
   live gate, modules that exist only to re-export (the root
   `src/multiword.rs` wrapper), the `verus/` directory
   (`feedback`: the pilot was aborted and should not be reattempted).
7. **Examples and benches.** Build every example and bench
   (`cargo build --examples`, `cargo bench --no-run`, with your target
   directory); does each demonstrate what its doc comment claims, and
   does any still use a pre 4.0 API spelling.
8. **The `ferrodec-decimal` surface.** `Context` construction ergonomics
   (`NonZeroU32`, `emax`/`emin` as raw `i32`), the `Work` type's
   invariants as prose versus as types, `interop` naming against the
   fixed formats.
9. **Error and status ergonomics.** `(value, Status)` tuples everywhere
   versus a result type; `Status` has no `Display` (B5); operator
   traits drop status (B3): is the contract stated once or rederived
   per call site.
10. **Module and file naming across the three format crates.** Same
    names, same order, same doc headers; any twin with a different
    name for the same thing is a maintenance cost; list them.
