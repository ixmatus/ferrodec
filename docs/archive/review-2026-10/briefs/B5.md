# Reader B5: `ferrodec-multiword` and `ferrodec-ieee` (Wave 3)

Lens: the two substrate crates every other crate stands on: fixed
width integer arithmetic (`U256` to `U1024`, `DecBig`, the constant
generators) and the shared IEEE kernel (`RoundingMode`, `Status`,
`should_round_up`, classification and digit tables, the binary float
helpers). A defect here is a defect everywhere; June found the
arithmetic clean and the Algorithm D add back branch uncovered.

## Scope (yours alone in this wave)

- `ferrodec-multiword/src/{lib,u256,u384,u512,u768,u1024,decbig,
  bigconst}.rs` (4,210 lines; `tests/decbig.rs` is 122 lines).
- `ferrodec-ieee/src/{lib,binary,classify,digits,round,status}.rs`
  (914 lines; one Kani harness).

Governing: ADR-0042 to 0046 (`DecBig` and the performance arc),
ADR-0060 (the adjudicator's `U1024` widths), ADR-0059 (`bigconst`
depths for the dynamic rung), `phase1b-derivations.md` §4 (the
generators pinned against mpmath), `wave2-verification.md` A4 (the
6,408 digit `2/π` table checked digit by digit; `DynArena` reads
`two_over_pi_digits(q + p + 70)` up to `6181 + p`), the June report's
multiword section.

## Checklist

1. **Limb boundaries, every width.** Shifts by 0, 1, 127, 128, 255,
   width − 1, width, and more than the width (panic, saturate, or
   mask: which, and is it documented and consistent across the five
   widths); add and sub carries across every limb boundary with all
   ones patterns; `wrapping`, `checked`, `overflowing` variants where
   they exist; comparisons across widths.
2. **Division.** Algorithm D's add back branch (the `q̂` overestimate
   case) for `U256`, `U512` and `U1024`: construct operands that
   force it (a divisor whose top limb is small and a dividend whose
   leading limbs make the estimate two too large is the classic
   shape; derive from Knuth 4.3.1 D, not from any implementation)
   and show the branch executes (a counter in a scratch copy, or
   `cargo llvm-cov` if installed) and the result matches `u128` or
   Python integer arithmetic; division by zero behaviour; remainder
   invariants `a = q·b + r`, `r < b`, on random and structured
   operands at every width against Python integers.
3. **Multiplication and widening.** `u256_mul_u256` into `U512` and
   the other widening products; `checked_mul`; conversions between
   widths (truncation on narrowing: panic, `Option`, or silent); the
   110 `as` casts in the crate with their bounds.
4. **`DecBig`.** Normal form invariants (no leading zero limbs, zero
   has a canonical form), digit counts at and around every power of
   ten up to the width (`decimal_digit_count(10^k)` and `10^k − 1`
   for every `k`), `from_ascii_digits` with leading zeros, `mul_pow10`
   and `div_rem_pow10` at the width edge, comparisons with mixed
   lengths, the string round trip, against Python integers; which
   invariants are `debug_assert` only and reachable from
   `ferrodec-decimal` (B4 reports the reachability, you report the
   invariant and the test).
5. **`bigconst`.** For each generator (`pi_digits`,
   `two_over_pi_digits`, `ln10` and its inverse, `inv_pi_digits`,
   any others): the claimed depth cap and the behaviour at and
   beyond it (panic message, saturation), termination, the guard
   digit argument in the doc, and one spot check at the generator's
   own maximum depth against mpmath (the coordinator pinned several
   depths; the cap itself is yours). The doc merge defect at
   `bigconst.rs:437-487` (`inv_pi_digits` inserted inside the
   `inv_ln10_digits` doc comment) is confirmed; record which public
   items carry no rustdoc as a result.
6. **`ferrodec-ieee::round`.** `should_round_up` against the §4.3
   table for all five modes and every (sign, guard, sticky, lsb odd)
   combination (the Kani harness covers this; read it and say what
   it does not cover, for example the `pre_sticky` composition used
   by `round_and_pack_finite`); `RoundingMode::for_negation` (every
   transcend kernel reflects through it: TowardPositive and
   TowardNegative swap, the nearest modes and TowardZero are fixed).
7. **`Status`.** The bit algebra (`|`, contains, `is_ok`, the CLAMPED
   bit, Display), the set semantics the docs claim, and whether any
   consumer relies on an ordering or a numeric value of the bits.
8. **`classify.rs`, `digits.rs`.** The digit count tables and
   thresholds pinned by value, not by identity; the class
   enumeration against §5.7.2 (`class` of `−0`, signaling NaN,
   subnormal).
9. **`binary.rs`** (changed since June): what it provides (`f64`
   decomposition, subnormal `f64`, NaN payload mapping, ties) to the
   format crates' `from_f64`/`to_f64`, against the `f64` bit level
   definition; B3 owns the format side.
10. **`no_std` and `const`.** Any `const fn` that can panic in a const
    context; any allocation; any `std` leakage under default
    features (`cargo build --target thumbv6m-none-eabi` for both
    crates with `--no-default-features` and with each feature).

## Extra deliverable

The add back coverage verdict with its reproducer and the pin table
(table or constant, value, the test that reads it).
