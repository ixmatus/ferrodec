# Reader D4: the reference registry, licensing and provenance (Wave 4)

Lens: durability of the record. Every external source the code, tests
and documents rely on has a registry entry that a maintainer in 2040
can follow; every vendored copy carries its license; every load bearing
URL has a dated archive; and the registry's own claims about coverage
and consumers are true.

## Scope (yours alone in this wave)

- `docs/references/**` (53 entries after Phase 0, `INDEX.md`,
  `SCHEMA.md`, `verification-map.md`, the generated
  `registry-status-flags.md`), `ferrodec-test-support/src/references.rs`
  and `tests/references_integrity.rs`, `tests/vectors/**` manifests
  and the `vendored/corpus integrity` tests, `tools/gen_lsz_d64_exp.py`,
  the `LICENSE*` files and the `license` fields in every `Cargo.toml`.
- `CLAUDE.md`'s registry paragraph and the README's "How ferrodec is
  developed" section read for truth only (never edited; any needed
  change is a diff proposal to Parnell).

Governing: ADR-0052 (the registry), ADR-0048 (CLAMPED's GDA
provenance), the global accretion schema in `CLAUDE.md`, the Phase 0
registry commit (`45807ba`: six entries repaired), `wave3-verification.md`
B5-7 (CLAMPED attributed to §7.4 and generated into the registry).

## Checklist

1. **Schema conformance, every entry.** Frontmatter fields against
   `SCHEMA.md`: citation with edition or revision, canonical URL or
   document number, archived URL with archive date, retrieval date,
   sha256 for binaries, license, vendor status, rot risk class,
   consumers, provenance class, verification linkage. The integrity
   test checks shape; you check truth: open each consumer path, each
   archived URL (does the Wayback capture exist and show the cited
   content; record the check date), each sha256 against the vendored
   file.
2. **License before vendoring.** For every vendored copy in tree
   (decTest under the ICU license, the LSZ d64 exp vectors under CC BY
   4.0 with attribution in `gen_lsz_d64_exp.py`, the campaign corpora
   and their `.prov` files, any constants tables or pseudocode taken
   from a paper): the license recorded, the attribution present where
   the license requires it, and the entry's `vendor-status` true.
   Paywalled standards (IEEE 754-2019, 1788) pointer only with clause
   numbers and the free proxy literature; confirm no copied text.
3. **Coverage gaps as disclosure inputs.** `cowlishaw-dectest.md`
   gaps 1, 4 and 5 were marked stale in planning; re-derive each
   conformance vector set's coverage gaps from the runners (C2's trust
   table: ten d64 files never dispatched, 99 skipped Conversion_syntax
   rows, d32 arithmetic uncovered) and compare with what the entries
   say; the README disclosure's named failure mode is fed from these,
   so a stale gap is a disclosure defect (diff proposal to Parnell).
4. **The six `failure-*` entries** against the current
   `KNOWN_ISSUES.md` files and the open beads this review filed (six
   P0s): which failures the registry records, which it should, and
   whether each entry's status is current.
5. **`verification-map.md`.** Every row points at a live artifact
   (test name, script, corpus); rows missing for the ADR-0059
   instruments (D2 lead), for the S2 campaign certifier, and for
   anything this review added (`docs/archive/review-2026-10/`).
6. **The generated registry text.** `registry-status-flags.md` is
   generated from `references_integrity.rs:137` and carries the false
   "§7.4" attribution for CLAMPED (B5-7): trace the generation path,
   list every other generated block and its source of truth, and
   check each against the code.
7. **Entries this arc must add.** Every source the review cites that
   has no entry: the Knuth Algorithm D reference (TAOCP 4.3.1) if
   `decbig.rs` cites it without an entry; Lauter and Lefèvre (the pow
   exact criterion); Niven's theorem as used by the pi family; the
   Payne and Hanek reduction paper; astro-float's `abs_cmp` defect
   (an upstream issue to file, recorded as a reference with the
   version); mpmath, python-flint and Arb versions as oracle
   references; the C23 draft entry's revision. Produce the entry
   drafts in the accretion schema in your report (the coordinator
   commits them in Phase 6).
8. **Provenance of code.** Spot check twenty functions whose rustdoc
   cites a paper or a reference implementation (decbig's Knuth,
   exact.rs's Lauter Lefèvre, argred's Payne Hanek, ln.rs's atanh
   reduction, the dpd declet equations): is the citation to the
   algorithm (fine) or does the code reproduce a particular
   implementation's structure (a provenance question for Parnell);
   report what you can see, not a legal opinion.
